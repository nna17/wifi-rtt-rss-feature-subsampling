# Feature Subsampling in Hybrid Wi-Fi RTT–RSS Fingerprinting

[![DOI](https://zenodo.org/badge/DOI/10.5281/zenodo.23092701.svg)](https://doi.org/10.5281/zenodo.23092701)

Code, experiment outputs, and LaTeX source for the paper

> **Feature Subsampling in Hybrid Wi-Fi RTT–RSS Fingerprinting: Radio-Map Density, Ratio Selection, and Calibration With Clustered Scans**
> Nabil Abdelkader Nouri (CSAAIL, University of Djelfa, Algeria) and Salim Naouri (Department of Computer Science, Southwest Jiaotong University, Chengdu, China).
> Submitted to the *Journal of Network and Computer Applications*.

The paper studies the number of candidate features per split, `m_try = max(1, floor(rho * p))`, of Random Forests on hybrid Wi-Fi RTT–RSS fingerprints: how its optimal value depends on radio-map density, how it should (and should not) be selected, and how conformal uncertainty regions behave when each reference point (RP) contributes many near-identical scans.

## Quick start: the notebook

The easiest way to check and reproduce the paper is [`reproduce.ipynb`](reproduce.ipynb). It explains each experiment in the order of the paper, shows the key results and plots, regenerates the paper's tables and figures, and runs **27 consistency checks** that compare the numbers stated in the paper with the result files.

```bash
pip install -r requirements.txt -r requirements-notebook.txt
jupyter notebook reproduce.ipynb
```

By default (`RUN_EXPERIMENTS = False`), the notebook uses the experiment outputs included in this repository, needs no data, and runs in about a minute. Set `RUN_EXPERIMENTS = True` (after placing the datasets in `dataset/`) to rerun the experiments from the raw data first. The notebook is generated by `scripts/build_notebook.py`; edit that script and rerun it instead of editing the notebook by hand.

## Requirements

Python 3.12 or later (tested with Python 3.14, scikit-learn 1.9.1, NumPy 2.4.4, pandas 3.0.3, SciPy 1.17.1, Matplotlib 3.10.9) and the packages in `requirements.txt`. No GPU is needed; all experiments were run on a laptop CPU (Intel Core i5-13500HX, 20 threads, 16 GB RAM).

## Data

The experiments use two public datasets, which are not redistributed here. Download them and place the files in `dataset/` with the exact names listed in [`dataset/README.md`](dataset/README.md).

## Reproducing the results

Every result in the paper can be regenerated from the data. The outputs of our runs are included, so the tables and figures can also be rebuilt without rerunning the experiments (steps 4–5 only).

| Step | Command | Output | Time* |
|---|---|---|---|
| 1. Main pipeline | `python run_all_paper_experiments.py` | `paper_results/`, `eetac_external_validation_results/` | ~10 min |
| 2. Extension experiments | `python scripts/extensions/paper_extensions.py` | `audit_results/extensions/E*.csv` | ~1.5 h |
| 3. Screening experiments (optional) | `python scripts/screening/claims_audit.py`<br>`python scripts/screening/new_ideas.py --tag small --datasets office,apartment`<br>`python scripts/screening/new_ideas.py --tag building --datasets building --seeds 0` | `audit_results/` | ~2 h |
| 4. Paper tables and figures | `python scripts/extensions/make_paper_tables.py`<br>`python scripts/extensions/make_extension_figures.py`<br>`cp paper_results/figures/fig*.{pdf,png} paper/figures/results/` | `paper/tables/`, `paper/figures/results/` | seconds |
| 5. Supplementary tables | `python scripts/extensions/make_supplementary.py` | `paper/supplementary/supplementary_tables.tex` | seconds |

\* On the laptop CPU above.

Individual extension experiments can be run with `--parts`, e.g. `python scripts/extensions/paper_extensions.py --parts E8,E9`. The default runs all parts used in the paper (E1, E2, E3, E3b, E5, E6, E7, E8, E9, E11). E4 is an earlier version of the calibration analysis, superseded by E8, and is not used in the paper.

### Seeds and determinism

The main pipeline uses seed 42. The extension experiments use seeds 0–9 (E1, E7, E9, E11) or 0–2 (E3, E3b, E5; Building in E3/E3b: seed 0 only), and E2, E6, E8 use seed 0. Values of the same configuration can therefore differ slightly between the main and the extension tables. With the same package versions, all accuracy, coverage, and area values are reproduced exactly; wall-clock training and inference times depend on the machine and its load.

### EETAC acquisition-day frames

The two EETAC acquisition days are recorded in vertically mirrored coordinate frames (Day 2 `y` corresponds to `8 - y` on Day 1). The EETAC engine detects this from the data by matching per-RP RTT fingerprints across days, applies the alignment before any pooled or cross-day experiment, and writes the evidence to `eetac_external_validation_results/day_frame_alignment_audit.csv`. Without the alignment, cross-day errors exceed 5 m; with it, they are 1.2–1.7 m.
